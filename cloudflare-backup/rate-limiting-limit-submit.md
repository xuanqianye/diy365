# Cloudflare Rate Limiting 规则备份（安全加固，2026-11-13）

> 用途：保护公开写接口 `/submit`（任何人可调用，直接用 GH_TOKEN 往 GitHub 仓库写文件），
> 防止脚本狂刷污染仓库 / 打爆构建流水线。与代码层 `functions/submit.js`（60秒/10次）形成双重限流。

## 当前生效的规则：limit-submit

| 配置项 | 值 |
|---|---|
| 规则名称 | `limit-submit` |
| 状态 | 活动 |
| 匹配条件（当传入请求匹配时） | 字段 **URI 路径** 运算符 **包含** 值 **`/submit`** |
| 计数特征（具有相同特征…） | **客户端 IP** |
| 速率阈值 | **10 次 / 10 秒钟**（Free 计划仅此窗口可选） |
| 操作（然后采取措施…） | **阻止（Block）** |
| 持续时间 | **10 秒钟**（被判定滥用后封禁时长） |

等价表达式：`http.request.uri.path contains "/submit"`

## 重建步骤（若规则丢失，照此在 Cloudflare 控制台重建）
1. 登录 Cloudflare → 选中站点 **diy365.cc** → 左侧 **安全性 (Security)** → **WAF** → **速率限制规则 (Rate Limiting Rules)**。
2. **创建规则**，按下表逐项填：
   - 名称：`limit-submit`
   - 匹配：URI 路径 包含 `/submit`
   - 计数特征：客户端 IP
   - 阈值：10 次 / 10 秒钟（如需更宽松用付费版可选 1 分钟窗口；当前 Free 计划只有 10 秒）
   - 操作：阻止
   - 持续时间：10 秒钟
   - 状态：活动
3. 点 **部署**。

## 注意事项
- Free 计划只允许 **1 条**速率限制规则（已用满，列表旁黄色感叹号为正常提示）。
- 该规则只保护 diy365.cc 下的 `/submit`；feetworld.cc 无此接口，不受影响。
- 与 `submit.js` 代码层限流互补：Cloudflare 拦突发（10秒/10次），代码拦慢速（60秒/10次）。
- 若升级到 Pro 等付费计划，建议把窗口改成 **10 次 / 1 分钟** 更合理（Free 仅 10 秒可选）。
